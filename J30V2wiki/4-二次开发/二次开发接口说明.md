# 二次开发接口说明

!!! info "📖 本章导读"
    * 本章面向有 ROS 或 Python 编程基础的开发者，介绍如何通过 ROS 话题接口**动态控制非凸-α 无人机**
    * 非凸-α 的规划器（Diff-Planner）不仅支持配置文件方式飞固定航线，还可通过暴露的 4 个主要的 ROS 话题接口，支持用户程序在运行时实时发送起飞、目标航点、返航、降落指令
    * 基于这些接口，你可以开发上层应用：巡检、定点巡逻、多机协作等

## 背景：为什么要用接口

在[自主导航](../3-功能模块/自主导航.md)一章中，你学到了"写配置文件 → 启动程序 → 无人机按顺序飞"的方式。这种方式适合**固定航线**——出发前就知道所有航点。

但很多场景需要**运行时决策**。举个例子——**巡检任务**：

> 无人机起飞 → 飞往巡检点 A → 拍摄照片 → **根据照片结果判断**：正常则飞往下一个点，异常则标记并跳过 → 全部完成 → 返航降落

这种"飞一步、看一眼、再决定下一步"的逻辑，无法用写死的配置文件实现。你需要在程序运行时动态调用接口。

非凸-α 的 Diff-Planner 提供了 4 个 ROS 话题，让你的程序可以在运行时指挥无人机。

---

## 一、ROS 话题接口

> ⚠️ 所有接口**必须在导航程序启动后**才能使用。启动方式见[自主导航 - 第四步](../3-功能模块/自主导航.md#第四步自主导航飞行)。

### 1.1 起飞

向 `/px4ctrl/takeoff_land` 话题发送起飞指令，无人机会自动爬升至配置文件中设定的起飞高度。

| 项目 | 内容 |
| --- | --- |
| 话题名 | `/px4ctrl/takeoff_land` |
| 消息类型 | `quadrotor_msgs/TakeoffLand` |
| 参数 | `takeoff_land_cmd: 1` |

**命令行调用**：

```bash
rostopic pub -1 /px4ctrl/takeoff_land quadrotor_msgs/TakeoffLand "takeoff_land_cmd: 1"
```

### 1.2 降落

向同一话题发送降落指令，无人机自动降落在当前位置。

| 项目 | 内容 |
| --- | --- |
| 话题名 | `/px4ctrl/takeoff_land` |
| 消息类型 | `quadrotor_msgs/TakeoffLand` |
| 参数 | `takeoff_land_cmd: 2` |

**命令行调用**：

```bash
rostopic pub -1 /px4ctrl/takeoff_land quadrotor_msgs/TakeoffLand "takeoff_land_cmd: 2"
```

### 1.3 发送目标航点

向 `/goal` 话题发送一个目标点坐标（x, y, z），Diff-Planner 会自动规划一条安全路径并飞行过去。

| 项目 | 内容 |
| --- | --- |
| 话题名 | `/goal` |
| 消息类型 | `geometry_msgs/PoseStamped` |
| 关键字段 | `pose.position.x`、`pose.position.y`、`pose.position.z` |

**命令行调用**（将 `x/y/z` 替换为你的目标坐标）：

```bash
rostopic pub /goal geometry_msgs/PoseStamped "header:
  seq: 0
  stamp:
    secs: 0
    nsecs: 0
  frame_id: ''
pose:
  position:
    x: 3.0
    y: 2.0
    z: 1.0
  orientation:
    x: 0.0
    y: 0.0
    z: 0.0
    w: 0.0"
```

| 字段 | 含义 | 示例值 |
| --- | --- | --- |
| `pose.position.x` | 目标点 X 坐标（米） | `3.0` |
| `pose.position.y` | 目标点 Y 坐标（米） | `2.0` |
| `pose.position.z` | 目标点 Z 坐标 / 高度（米） | `1.0` |
| `pose.orientation` | 四元数姿态（通常用默认值即可） | `w: 0.0` → 自动对准轨迹方向 |

> 💡 **如何确定坐标**：可以使用[自主导航 - 打点教程](../3-功能模块/自主导航.md#第三步打点教程)中的打点方法获取环境中的位置坐标。

### 1.4 触发返航

向 `/back_trigger` 话题发送返航点坐标，无人机完成当前任务后将飞回该点。

| 项目 | 内容 |
| --- | --- |
| 话题名 | `/back_trigger` |
| 消息类型 | `geometry_msgs/PoseStamped` |

**命令行调用**：

```bash
rostopic pub -1 /back_trigger geometry_msgs/PoseStamped "header:
  seq: 0
  stamp:
    secs: 0
    nsecs: 0
  frame_id: ''
pose:
  position:
    x: 0.0
    y: 0.0
    z: 0.5
  orientation:
    x: 0.0
    y: 0.0
    z: 0.0
    w: 0.0"
```

## 二、调用示例：巡检场景

以下是一个巡检任务的**伪代码**，演示如何串联 4 个接口。你可以用 Python + [rospy](http://wiki.ros.org/rospy) 或 C++ + [roscpp](http://wiki.ros.org/roscpp) 实现：

```python
# 假设你已启动导航程序，无人机在地面待命

# 1. 起飞
pub_takeoff.publish(takeoff_msg)       # takeoff_land_cmd = 1
sleep(5)                                # 等待爬升至起飞高度

# 2. 依次飞往各巡检点
inspection_points = [
    (3.0, 2.0, 1.0),    # 巡检点 A
    (6.0, 1.0, 1.5),    # 巡检点 B
    (9.0, 0.0, 1.0),    # 巡检点 C
]

for point in inspection_points:
    goal = PoseStamped()
    goal.pose.position.x = point[0]
    goal.pose.position.y = point[1]
    goal.pose.position.z = point[2]
    pub_goal.publish(goal)               # 发送目标点
    sleep(10)                            # 等待飞行到达（实际应根据里程计判断）

# 3. 返航
back_msg = PoseStamped()
back_msg.pose.position.x = 0.0
back_msg.pose.position.y = 0.0
back_msg.pose.position.z = 0.5
pub_back.publish(back_msg)              # 触发返航
sleep(10)                               # 等待返航

# 4. 降落
pub_land.publish(land_msg)              # takeoff_land_cmd = 2
```

> 💡 以上为简化示例。实际应用中，建议通过订阅里程计话题（如 `/ekf/ekf_odom`）判断是否到达目标点，而不是固定 `sleep` 等待。

## 三、注意事项

1. **必须先启动导航程序**：所有接口只有在 `Diff-Navigation` 程序运行期间才有效。启动前发送的指令会被忽略。
2. **坐标系**：所有坐标（x, y, z）均以起飞时刻的无人机位置为原点（body frame）。确保航点坐标在虚拟墙范围内（默认天花板 2.0m、地板 0.1m）。
3. **接口间无内置互锁**：发送起飞指令后，请等待无人机爬升至目标高度再发送航点；发送新航点时，上一个航点任务会被覆盖。
4. **命令格式不能出错**：`rostopic pub` 的 YAML 格式对缩进敏感。建议先在终端手动测试每条命令，确认有效后再写入代码。
5. **`rostopic pub` 中的 `-1` 标志**：表示"只发布一次消息，然后退出"。起飞、降落、返航用 `-1`（一次性触发），目标点 `/goal` 不用 `-1`（持续发布直到到达）。
6. **安全第一**：开发调试时，**始终保持遥控器在手**。如果程序行为异常，立即按 SE 键切换悬停或 SC 键紧急上锁。
